# Tamper vectors (manifest spec v0.1)

Generated by `node test/tools/make-tamper-vectors.mjs` (`--check` verifies); deterministic from the RFC 8032
section 7.1 seeds, so a rerun reproduces every byte. Vendored byte for byte into
`control-plane/crates/cp-manifest/tests/fixtures/vectors/tamper/`. Spec release 0.4.0, manifest 0.1.1.

Base manifest: id `tamper-base`, version `1.1.0`, `createdAt` `2026-11-01T00:00:00Z`, `expiresAt`
`2027-11-01T00:00:00Z`, the four entries of vector 05, signed with `rfc8032-1`. Every row of `tamper.json`
runs at the fixed clock `now` = `2026-11-14T00:00:00Z`, so the results do not change when the base manifest
expires.

## Trust names

| Name        | RFC 8032 section 7.1 | Public key                                                         |
| ----------- | -------------------- | ------------------------------------------------------------------ |
| `rfc8032-1` | TEST 1               | `d75a980182b10ab7d54bfed3c964073a0ee172f3daa62325af021a68f707511a` |
| `rfc8032-2` | TEST 2               | `3d4017c3e843895a92b70aa74d1b7ebc9c982ccf2ec4968cc0cd55f12af4660c` |

Both are test keys: every row except `tamper-14` runs with `allowTestKeys` true. The seeds are in
`../../examples/TEST-KEY.md`.

## Row shape

`tamper.json` is an array of `{ file, trust, allowTestKeys, now, state, requiresState, expect }`:

- `trust`: the trust set, as names from the table above;
- `allowTestKeys`: the boolean passed to the verifier (a strict boolean);
- `now`: the verifier's clock for the row;
- `state`: the stored downgrade state `{ version, createdAt }`, or `null` for none;
- `requiresState`: true when the row needs a downgrade store; an implementation without one skips the row
  and says so (`tamper-08` and `tamper-09`);
- `expect`: `{ valid, stage?, reason?, signatures? }`. `stage` is `parse` or `verify`. `signatures` lists
  the per-signature results in order (`bad_signature`, `key_mismatch`, `untrusted_key`, `unknown_alg`,
  `malformed_sig`, `malformed_key_id`, `valid`). `tamper-14` has only `valid` and `reason`:
  `test_key_refused` is raised before parsing and is the only reason that throws.

## Files

| File                                  | Change                                                           | Expected                              |
| ------------------------------------- | ---------------------------------------------------------------- | ------------------------------------- |
| tamper-01-entry-sha-byte.json         | one hex character of `entries[1].sha256` changed after signing   | `no_valid_signature`, `bad_signature` |
| tamper-02-entry-size.json             | `entries[0].size` plus one                                       | `no_valid_signature`, `bad_signature` |
| tamper-03-sig-bitflip.json            | one bit of `sig` flipped                                         | `no_valid_signature`, `bad_signature` |
| tamper-04-swapped-key.json            | `keyId` and `publicKey` of key 2, `sig` made by key 1            | `no_valid_signature`, `bad_signature` |
| tamper-05-publickey-mismatch.json     | `keyId` of key 1, `publicKey` of key 2                           | `no_valid_signature`, `key_mismatch`  |
| tamper-06-untrusted-key.json          | validly signed by key 2; trust is key 1 only                     | `no_valid_signature`, `untrusted_key` |
| tamper-07-truncated.txt               | the signed file cut at floor(length / 2); not JSON               | `invalid_json`, parse                 |
| tamper-08-rollback.json               | version 1.0.0, validly signed                                    | `downgrade` (state 1.1.0)             |
| tamper-09-replay-older-createdAt.json | 1.1.0, `createdAt` 2026-10-01T00:00:00Z, validly signed by key 1 | `downgrade` (state 1.1.0)             |
| tamper-10-expired.json                | `expiresAt` 2026-11-10T00:00:00Z, validly signed                 | `expired`                             |
| tamper-11-rotation-ok.json            | signatures: key 2 (valid, untrusted), key 1 (valid, trusted)     | VALID: `untrusted_key`, `valid`       |
| tamper-12-stripped.json               | `signatures` is empty                                            | `no_valid_signature`                  |
| tamper-13-alg-none.json               | key 1's signature labelled `none`                                | `no_valid_signature`, `unknown_alg`   |
| tamper-14-test-key-refused.json       | the base manifest; trust is key 2; `allowTestKeys` false         | throws `test_key_refused`             |
| tamper-15-noncanonical-s.json         | S replaced by S + L (little-endian), still 64 bytes              | `no_valid_signature`, `bad_signature` |

`tamper-15` is the classic Ed25519 malleability: a verifier that does not require S < L accepts it. The
signature of `tamper-09` is checked to verify under key 1 when the file is generated, so the only fault in
that row is the older `createdAt`.
