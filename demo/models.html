runtime backend demo

What can this device run, and does a small model answer a prompt on it? Everything happens in this tab. Nothing is uploaded, and nothing is requested from this site's models/ folder until you click the download button.

Built from main at ? by .github/workflows/pages.yml. Asset manager demo.

What this demo shows

Same prompt answered on WebGPU and on WebAssembly with the test model SmolLM2-135M-Instruct (q4), in Chrome on an Apple-silicon Mac only. This is not the Hindi production model; Windows and the 8 GB no-GPU laptop are not measured.

Planned production model: Qwen3-1.7B (Apache-2.0), WebGPU q4f16 1.43 GB, WASM q8 1.74 GB. Provisional until the Sprint 5 measurement on an 8 GB laptop; contingency Qwen3-0.6B. Loaded once in a browser: a local, unscored WebGPU smoke run of five synthetic Hindi prompts on an Apple-silicon Mac, which needed ONNX Runtime graph optimisation turned off (evidence/sprint-2/D1/hindi-smoke.json).

What this demo does not do yet

  • Test model only (SmolLM2-135M-Instruct q4, English): the Hindi production model is not hosted or bundled here (Sprint 5).
  • WebGPU is verified only on an Apple-silicon Mac; Windows and the 8 GB no-GPU laptop are not measured.
  • WebLLM backend: Sprint 3.
  • This page freezes while WebAssembly generates: the engine runs on the main thread, so the tab does not repaint or run timers until generation ends, and answers are kept short there. Moving the engine off the main thread is planned for Sprint 3.
  • If WebGPU fails after the engine has started (for example out of memory), WebAssembly cannot start in the same page: reload the page and tick Force WASM.
  • No threads: GitHub Pages cannot send the COOP and COEP headers, so WebAssembly runs on one thread and is slow.
  • The Chrome built-in model is used only if you tick the box below and the browser reports it already available; it is Google's model, not hash-verified by us.
  • No service worker: offline after the first load is best effort, not guaranteed.
  • The model manifest is signed by a key generated for this build only (never written to disk), so it proves the verification path, not a publisher identity.
