Everything runs in this tab. Nothing is uploaded; the only network requests are for this page's own files and for a manifest URL you paste yourself.

The ?manifest=range parameter is honoured only on 127.0.0.1 or localhost (it points the page at the repository's range test server). On this host it is ignored and the bundled fixture stays the manifest source.

Browser requirements

  • ? WebAssembly
  • ? OPFS (navigator.storage.getDirectory, secure context)
  • ? IndexedDB
  • ? Web Locks (navigator.locks)
  • ? WebCrypto Ed25519 (crypto.subtle present; actual Ed25519 support is reported from the first verify)
  • ? WebGPU (optional, used by the capability profile only)

All Airplane Mode Labs demos share one browser origin (airplanemode-labs.github.io): storage, quota, estimate() and persist() are shared between them. This demo writes only under airplanemode-runtime.

Tested in Google Chrome. Firefox and Safari are not tested this sprint.

What this demo does not do yet

  • No model is downloaded. The three assets are synthetic xorshift64* byte streams of 12, 8 and 6 MiB, generated at build time; they prove download, resume, hashing and eviction, not inference.
  • No backend adapter: WebGPU and WASM inference with the fallback chain arrives in Sprint 2. Only the interface and a mock adapter exist today.
  • The fixture manifest carries no expiresAt and is signed by a key generated for this build only, so it proves the verification path, not a publisher identity.
  • No key revocation, transparency log or Sigstore (security finding S1-001).
  • Chrome's real IndexedDB quota is unmeasured here; use the test quota field to see eviction. Chrome under-reports IndexedDB usage in estimate().
  • Resume after an interrupted download is verified on the local Range server and on GitHub Pages (checked 9 Nov 2026: Range: bytes=0-1023 on the fixture answered 206 with Accept-Ranges: bytes). If a host ever answers 200 instead of 206, the download restarts from zero and is still hash-verified.
  • No service worker: offline after the first load is best effort (Chrome's HTTP cache), not guaranteed.

Settings

Changing the store reloads the page with ?store=.

Test hooks (window.__runtime) exist only on 127.0.0.1 / localhost; a hosted page never exposes them.

Capability profile

detectCapabilities(): allow-listed device facts (cores, memory tier, storage estimate, WebGPU adapter vendor and limits, WASM features). Never reads navigator.userAgent.

Quota and eviction

        

          Without a test quota the manager plans against navigator.storage.estimate()
          with the production headroom of 67108864 bytes (64 MiB). The walkthrough sets a 24 MiB
          test quota and 1 MiB headroom, downloads demo-a (12 MiB) and demo-b (8 MiB), then demo-c
          (6 MiB): 20 + 6 + 1 exceeds 24, so the least recently used entry is evicted.
