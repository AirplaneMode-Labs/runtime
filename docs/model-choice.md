# Model choice (Sprint 2)

Status: **planned, provisional**. This document records the model decision the owner delegated to the
architect, the licence rule it was made under, the evidence behind it and what has not been
measured. Every size below equals the value in [`test/tools/models.json`](../test/tools/models.json)
byte for byte (a test checks this); every Hindi figure was read by the lab in the cited source on
9 November 2026. **The lab has run no Hindi evaluation of its own** and none of the numbers below
comes from the lab.

## Decision

Planned production model: Qwen3-1.7B (Apache-2.0), WebGPU q4f16 1.43 GB, WASM q8 1.74 GB. Provisional until the Sprint 5 measurement on an 8 GB laptop; contingency Qwen3-0.6B.
Loaded once in a browser: a local, unscored WebGPU smoke run of five synthetic Hindi prompts on an Apple-silicon Mac, which needed ONNX Runtime graph optimisation turned off (evidence/sprint-2/D1/hindi-smoke.json).

- Weights: `onnx-community/Qwen3-1.7B-ONNX@3231b522c6e703b2f9b3cd8ea27426a1289a02f2` through
  Transformers.js: WebGPU `onnx/model_q4f16.onnx` (1,426,069,098 B), WASM
  `onnx/model_quantized.onnx` (1,742,387,852 B).
- Thinking mode is off: the descriptors carry `generation.chatTemplateKwargs` `{"enable_thinking": false}`.
- Contingency, if the 8 GB measurement fails: Qwen3-0.6B (`onnx-community/Qwen3-0.6B-ONNX`), q4f16
  569,789,750 B and q8 617,687,575 B.
- The `onnx-community` repository carries no licence metadata of its own (its card front matter has
  only `library_name` and `base_model`), so an offline bundle ships the base model's Apache-2.0
  `LICENSE`, a provenance record (repository and 40-hex revision) and a `NOTICE`. That pilot licence
  package is not built this sprint (PRE-PILOT-CHECKLIST).
- WebLLM is information only here: the WebGPU build `mlc-ai/Qwen3-1.7B-q4f16_1-MLC` is
  984,156,278 B in total; the WebLLM adapter is Sprint 3.
- Descriptors (spec `model-descriptor.schema.json`): `qwen3-1.7b.tjs-webgpu-q4f16` (devices `webgpu`,
  dtype `q4f16`, `minProfile` WebGPU with `backendTier` `webgpu-f16`, `ramGb` 8) and
  `qwen3-1.7b.tjs-wasm-q8` (devices `wasm`, dtype `q8`, `backendTier` `wasm-simd`, `ramGb` 8). The q8
  descriptor is documented only and not run.
- Result of the local browser smoke run (D1-09, `evidence/sprint-2/D1/hindi-smoke.json`): Qwen3-1.7B
  q4f16 **loaded in Chrome on WebGPU and answered five synthetic Hindi prompts** (one BFSI-style, an
  invented loan-statement sentence), unscored, on an Apple-silicon Mac only. The default chain selected
  the `webgpu` rung (no `forceRung`), behind the aborting network gate, with every file served from the
  loopback server and verified against a signed manifest first. Load 16887 ms for 1,462,064,779 B, mean 28.2 tokens per
  second, peak JS heap 76,495,528 B, at most 128 new tokens per prompt, temperature 0, thinking off. The outputs
  are recorded verbatim in the evidence file; **nothing was scored**, two of the five stopped at the
  128-token budget, and nothing here says the Hindi is good. The decision stays **provisional**: this is
  one machine with 32 GB, not the 8 GB Windows laptop.
- **Finding: it only loads with `graphOptimizationLevel: 'disabled'`.** With ONNX Runtime Web's default
  graph optimisation the session cannot be created (`ERROR_CODE: 6, ERROR_MESSAGE: std::bad_alloc`,
  after about 15 s); `'basic'` fails the same way and `'disabled'` loads. The single 1.43 GB file plus
  its optimised copy do not fit the 4 GB WebAssembly heap. Descriptor 0.1.0 has no field for session
  options, so the adapter takes `sessionOptions: { graphOptimizationLevel }` from the application (the
  only session option it accepts) and the local hook sets it for this model. This needs an architect
  decision (a descriptor field, or external-data weights) before the production model works through
  `createDefaultAdapters()` without application help, and it is one more reason the 8 GB laptop
  measurement in Sprint 5 matters.
- **What that means in practice:** the q4f16 session only builds with graphOptimizationLevel 'disabled' because the default fails with std::bad_alloc in the 4 GB wasm32 heap; createDefaultAdapters() cannot load the production model unless the application passes the sessionOptions option; the descriptor field for this is an architect decision for Sprint 3. The sessionOptions allow-list stays at that one key.

## The decision rule (the lab's stricter rule)

The owner delegated the model choice to the architect. The architect set this rule:

1. The licence must allow commercial use and redistribution inside offline bundles, and the lab
   accepts **no custom licence and no use-policy pass-through** inside Apache-2.0 offline bundles
   sold to regulated buyers (an Apache-2.0 or MIT licence, or an equivalent standard licence).
2. Under 2 GB to download in a quantisation the browser can run.
3. Evidence that the model handles Hindi (sourced, not assumed).
4. Runs in the browser through Transformers.js and/or WebLLM on WebGPU and on WebAssembly.
5. Among models that pass 1 to 4, the smaller one.

**Llama 3.2 and Gemma do allow commercial use and redistribution.** Both licences permit it, under
conditions, so they are _not_ rejected for forbidding commercial use. They are rejected under the
stricter rule above, because both require terms to travel with the weights and both reserve
conditions that an Apache-2.0 bundle sold to a regulated buyer cannot express: the Llama 3.2 Community
Licence needs "Built with Llama" attribution, acceptable-use-policy pass-through and has a 700 million
monthly-active-user clause; the Gemma Terms of Use need their prohibited-use policy passed through as
an enforceable provision and let Google restrict usage. This is a decision of the lab, not a claim
that either licence fails the owner's rule as originally stated.

Note that the rule is not size-driven: at q4f16 the Llama and Gemma downloads are smaller than
Qwen3-1.7B.

## Test and CI model

`HuggingFaceTB/SmolLM2-135M-Instruct@12fd25f77366fa6b3b4b768ec3050bf629380bac`, file `onnx/model_q4.onnx`,
182,068,553 B, sha256 `933577110303a2964096d19b6f15d3b4639bef7f99481ac0b61d9f3ad72f392a` (Apache-2.0).

It is the smallest model that exercises both backends: the same q4 weights run on the ONNX Runtime
WebGPU and WebAssembly execution providers, so one file proves the fallback chain on both devices. It
is English and about 135M parameters: it says nothing about Hindi quality and is never offered as the
production model. It is downloaded once into the gitignored `.cache/models/` by
`node test/tools/fetch-model.mjs smollm2-135m-instruct` and never committed.

## What is not decided or not measured

- Whether Qwen3-1.7B (or the Qwen3-0.6B contingency) fits and is fast enough on an 8 GB Windows laptop
  with no GPU: Sprint 5, from measurements. Nothing was measured on that machine in Sprint 2.
- Hindi quality: no independent evaluation by the lab exists. Qwen3's published tables do not isolate
  Hindi, so "supports Hindi" here means "named in the training and evaluation language lists", not a
  measured score.
- Hosting or bundling any Hindi model in a demo or Pages artifact: not done (Sprint 5).
- Qwen3 q8 on WebAssembly: documented, not run.
